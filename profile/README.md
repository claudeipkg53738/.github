<p>一套住宅 IP 资源用到第三个月，出问题的往往不是线路本身，而是管理：新同事不清楚哪个出口对应哪个账号，成员离开后凭据还留在共享文档里，凌晨线路掉线没人收到通知，月底对账才发现有三条资源已经空转两个月。下面按五层拆开，从资源池怎么切到权限怎么收，每层给一个能当天落地的最小做法，不追求一步到位。</p>

<h2>一、第一层：资源池按什么维度切</h2>
<p>切分维度决定后面所有规则的天花板。切得太细，一条线路只服务一个账号，成本上去了却不见得更稳；切得太粗，十个人抢三个出口，出问题谁也说不清。先看业务里有几个天然分隔。</p>
<h3>按团队切：内部与外部必须分开</h3>
<p>内部运营和外部协作方共用同一批出口，最直接的后果是排查时无法确认操作来源。按团队切一层，再在团队内部按账号切第二层，两层叠加后责任边界清晰，成本增加有限。</p>
<h3>按账号生命周期切：新号与老号不混用</h3>
<p>刚注册的账号更需要干净且固定的出口，老账号对出口变化的容忍度略高。两类放进同一个池子随机分配，等于让新号承担了老号的历史。分组时把注册 30 天内的账号单独标出来，是最省事的隔离方式。</p>
<h3>按地区切：跨境业务的硬约束</h3>
<p>账号注册地、常用登录地与出口所在地三者不一致，是最常见的异常来源之一。地区分组不是可选项而是前置条件；同一地区内再按运营商或网段细分，能进一步降低关联概率。</p>

<h2>二、第二层：分组命名要能自解释</h2>
<p>分组做完了却没人看得懂，等于没做。命名规则的目标很朴素：任何人看到标签，不用翻文档就知道这条线路归谁、干什么用、什么时候到期。</p>
<h3>命名公式固定四段</h3>
<p>建议用「地区-类型-序号-责任人」四段，短横线连接，例如 us-static-07-zhang。类型段至少区分静态住宅、动态住宅、机房三类，不要临时自创缩写。责任人段写工号或拼音，别写昵称，昵称会随人变动。</p>
<h3>标签要能回答三个问题</h3>
<p>谁在用、给哪个账号用、什么时候到期。前两个决定权限，第三个决定续费提醒。很多团队只管前两个，结果到期线路被回收，账号当天的登录环境就变了，人却不知道原因。</p>

<h2>三、第三层：白名单与准入怎么设</h2>
<p>准入是资源管理里最容易被跳过的一环。默认所有人可见可用，短期方便，长期一定会出现「谁把这条线路删了」的悬案。</p>
<h3>源地址白名单与使用人白名单分开维护</h3>
<p>源地址白名单限制的是从哪台机器能连，使用人白名单限制的是谁能申请。两者变更频率完全不同：机器变动少，人员变动多。混在一张表里维护，改一次要动两处，出错概率翻倍。</p>
<h3>申请流程压到一页纸</h3>
<p>写清四件事就够：用途、账号数量、预计使用周期、退出时怎么回收。超过一页的流程没人看，最后又回到口头申请，台账随之失真。</p>

<h2>四、第四层：异常监控先上哪几个指标</h2>
<p>监控项铺得太多，告警会被自动忽略。住宅线路的管理场景里，四五个指标已经能覆盖绝大多数问题，先上这些，跑稳三个月再考虑加。</p>
<h3>可用率与延迟分开设规则</h3>
<p>可用率按 5 分钟粒度探测，连续三次失败再告警，避免瞬时抖动刷屏。延迟看分位数而不是平均值：平均 200 毫秒、P95 到 900 毫秒的线路，体验已经很差，平均值却看不出来。</p>
<h3>出口地址变化单独一条规则</h3>
<p>静态住宅的核心承诺是地址不变。一旦探测到出口地址与台账记录不一致，无论业务当前是否受影响都要告警，因为账号侧的感受往往滞后几小时才出现，等业务报错就晚了。</p>

<h2>五、第五层：成员权限与操作留痕</h2>
<p>权限设计的目标不是防人，而是让「谁在什么时候改了什么」这句话有答案。三级角色足够覆盖多数团队，再细就会变成负担。</p>
<h3>查看、使用、管理三级分开</h3>
<p>查看只能看台账和监控，不能取用凭据；使用可以取用但不能改线路；管理可以增删改。新成员默认给查看，观察一周再升级，比一开始就给管理权限稳妥得多。</p>
<h3>留痕的最小字段</h3>
<p>时间、操作人、对象、动作、变更前后值，五个字段就够。凭据轮换、线路删除、分组调整三类操作必须留痕，其余可以只记日志、不强制填写理由，否则没人愿意填。</p>

<h2>常见问答</h2>
<h3>小团队只有三五个账号，也需要做分组吗？</h3>
<p>答：需要，但可以极简。至少保留地区和责任人两个字段，写在共享表格里即可，不必上系统。规模扩大时，这两个字段就是迁移的基础，补记录比补结构省事得多。</p>
<h3>白名单里加了办公网固定地址，出差时怎么办？</h3>
<p>答：为出差场景单独准备一条带账号密码鉴权的通道，与白名单通道并存，用完即撤。不要为了临时方便把白名单放宽到整个网段，那是把风险留给以后。</p>
<h3>告警每天几十条，怎么收敛？</h3>
<p>答：先按是否需要人处理过滤，把纯提示类降到日报；再把同一线路的重复告警合并成一条并附持续时长。收敛后仍嫌多，多数是阈值设得太紧。</p>
<h3>成员离开时，除了改密码还要做什么？</h3>
<p>答：撤使用权限、轮换其经手过的凭据、核对台账责任人字段、检查有没有未登记的临时线路。四步做完再关闭账号，顺序别反。</p>
